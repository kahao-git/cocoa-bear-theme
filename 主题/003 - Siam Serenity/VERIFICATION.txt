4. Colour pass
--------------
All theme_values.xml colour literals remapped from the previous palette to the
Siam palette (28 RGB keys, alpha prefixes preserved). PNG assets duotone-mapped
through a 7-stop emerald-to-cream LUT. Protected by design: icons, wallpapers,
lock screen art, weather glyphs, widget plates, notification shade, heads-up card,
SMS bubbles and composer.

Dialog, popup and window backgrounds are intentionally restored to the system
originals (miuix_appcompat_window_bg_light, settings window bg, search mask,
new_message_popup_bg, alert_btn).


4b. Popup / dialog surfaces (system default)
--------------------------------------------
113 colour keys were removed from the theme_values.xml of com.android.mms (25),
com.android.settings (33), com.android.contacts (36), com.android.systemui (16)
and com.miui.home (3). Any key naming popup, dialog, bottom_menu, dropdown,
action_mode, snackbar or alert is no longer overridden, so MiuiX uses its own
light surface with dark labels.
Nine-patch dialog backgrounds stay on the untouched originals:
miuix_appcompat_window_bg_light.9.png, new_message_popup_bg.9.png, alert_btn.9.png
(mms), miuix_appcompat_settings_window_bg_light.9.png and
miuix_appcompat_window_search_mask.9.png (settings).
Where the popup is set: <module>/theme_values.xml - remove or add a key there to
control any popup surface; the bitmap itself comes from the module's
res/drawable-xxhdpi nine-patch.

8. Known limitations
--------------------
- .mtz is a plain zip (manifest + modules + preview/), unsigned; Theme Editor
  export is unavailable on this workstation.
- MAML verified structurally and by rendered preview, not on a physical device.
- Circle elements fall back to a solid tint if a device ignores animated alpha.
- Two timing_button nine-patches keep the inherited marker quirk (see 3).

9. Touch routing fix (build r2)
-------------------------------
MAML conditions were normalised to the escaped operator form (`&amp;&amp;`, `&lt;=`,
`&gt;=`). The earlier `**` spelling was read as two multiplications, so every
condition evaluated to a positive number - i.e. always true - and one tap fired
the torch, the camera, the weather app and the calendar together.
Lock screen actions now launch by action=MAIN + category=LAUNCHER + package
instead of a hard-coded Activity class, and the torch / camera zones scale with
#screen_height so they stay on the bottom corners on any resolution.
